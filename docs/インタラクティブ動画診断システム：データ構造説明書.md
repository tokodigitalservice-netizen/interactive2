# インタラクティブ動画診断システム：データ構造説明書

本システムは、JSON形式の設定ファイルによって動画の遷移、質問文、ボタンラベル、および誘導先URLを動的に制御する仕組みです。

## 1. ルート設定（全体設定）
JSONのトップレベル（`q`で始まらないキー）には、アプリ全体の基盤となる設定を記述します。

| キー名 | 説明 |
| :--- | :--- |
| `totalSteps` | 進捗バーの基準となるステップ数（数値）:現在進捗バーは非表示で未使用 |
| `currentURL` | 動画ファイルが格納されているベースURL（ディレクトリパス）。 |
| `closeUrl` | 右上の「バツボタン」を押した際に遷移する共通URL。 |

## 2. 各ノード（質問/遷移画面）の構造
個別の画面設定は、キー名（`q1`, `q1A`, `end1` など）をIDとして各オブジェクトを定義します。

### ノードの必須プロパティ
* **`text`**: 画面に表示する質問文。（現在非表示）
* **`videoUrl`**: 表示する動画ファイル名。`currentURL` の後ろに結合されて動画が読み込まれます。
* **`button`**: 画面に表示するボタンのラベル設定。JSONの記述順（上から順）に、左からボタンが生成されます。
* **`choices`**: 選択肢の遷移先定義。
    * **値 (Value)**: 次に読み込むべきノードIDを指定します。
    * **キー (Key)**: `choices` と `button` の順番を紐付けるための識別子です。

## 3. 特殊なノード
### 終了画面（IDが `end` で始まるノード）
診断のゴール地点となる画面です。
* **`result`**: 画面中央に表示される最終結果テキスト。
* **`endUrl`**: 終了画面に表示されるボタンを押した際の遷移先URL。
* **`endMessage`**: 終了ボタンに表示するメッセージラベル。

---

## 4. 運用・拡張ルール

### ボタンの動的生成
本システムは `choices` のキーの数だけボタンを自動生成します。
* **ボタンを増やしたい場合**: JSONの `choices` に新しいキーを追加し、`button` に対応するラベルを追記するだけで、自動的にボタンが増えます。
* **ラベルの紐付け**: `choices` と `button` はオブジェクトの記述順序（インデックス）で対応付けられます。したがって、**必ず両方のオブジェクト内で順番を一致させて記述してください。**

### 動画ファイルの指定
動画ファイルは以下のルールで自動的に決定されます。
1. `videoUrl` に指定されたファイル名が `currentURL` と結合されます。
2. サーバー側（R2など）のディレクトリパスが変更になった場合、`currentURL` を書き換えるだけで全動画のパスを追従可能です。

### 遷移ロジックのポイント
* `choices` の値は、次ステップのIDを指し示します。これにより、複雑な分岐（戻るボタンなど）をノードIDの指定だけで実現可能です。
* `end` で始まるIDを指定すると、システムは自動的に「結果表示モード」に切り替わり、通常の選択肢ボタンの代わりに終了遷移ボタンを表示します。
